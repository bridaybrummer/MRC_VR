# Town Planning Dashboard

A Vite + React dashboard for querying Cape Town ERFs, retrieving City Land Parcel cadastre, and producing TBTP-style startup planning reports with production-grade figure plates.

The core workflow is: search or click an ERF, pull City Land Administration data, confirm raw cadastre evidence, load required figure data, and publish a TBTP PDF or Word report. The dashboard supports ERF number, SG26 code and ISIS/LIS key lookup, plus parcel selection from the interactive City map.

The bundled starter records remain useful for workflow testing, but production report outputs are driven by live or cached City GIS evidence where available. Publishing is gated by required data readiness: Land Parcel cadastre and a Figure 5 zoning source must be available before PDF/Word export unlocks.

## Architecture

- `src/data/demoProperties.ts` contains 53 Cape Town Metro starter records for search, selection, map and report workflow testing.
- `src/data/sourceRegistry.ts` lists public and local data sources to connect during rollout.
- `src/data/publicDataInventory.ts` stores researched public layer counts, estimated raw JSON size, import priority and validation risk, including City parcel, road-centreline and Ground Level Map sources.
- `src/data/generatedLayerFreshness.ts` is generated by the build-time metadata checker and records whether public layers are current or need update.
- `src/components/CityErfMap.tsx` renders the single interactive City of Cape Town map (Leaflet aerial/streets basemap) with zoning-coloured office erven, the live selected parcel boundary, neighbouring City erven for context, and road/contour layers.
- `src/components/ErfSearchConfirm.tsx` provides the search-confirm workflow: query City parcels by ERF number, show multiple candidate matches with summary info (ward, suburb, extent, zoning), and let the user confirm the correct property before data retrieval begins.
- `src/data/suburbCentroids.ts` provides planning-grade suburb coordinates used to plot office erven on the real basemap until every record carries a live cadastral match.
- `scripts/check-public-layer-updates.mjs` checks ArcGIS item metadata only; it does not download or import layer data.
- `scripts/sync-split-zoning-cache.mjs` downloads the City Open Data Split Zoning GeoJSON into `public/city-cache/split-zoning.geojson` for deterministic Figure 5 fallback rendering.
- `scripts/check-city-cache.mjs` validates required local cached City data before production builds.
- `src/services/localPropertyAdapter.ts` imports local CSV records without coupling the UI to a specific office database.
- `src/services/cityPropertyRecordService.ts` converts City Land Parcel matches into reportable property records.
- `src/services/reportTemplate.ts` produces the standardized planning report from a typed property record.
- `src/services/documentPublisher.ts` creates the branded Word-compatible report download.
- `src/planningTypes.ts` defines the core property, zoning, data-audit, source and report contracts.

## Report Publishing

The `templates` directory stores the current reporting references:

- `templates/11645 - Motivation Report - Rev 2.doc`
- `templates/11645 - Motivation Report - Rev 2.pdf`

The dashboard uses these as the formatting reference for the generated startup report. The report tab includes editable publishing fields for consultant firm, prepared by, client, reference, revision and application type. The default logo is served from `public/branding/tommy-200-logo.jpg`.

Use `Publish PDF` to open the browser print flow. The print stylesheet outputs an A4 report-only document with the branded cover, logo, consultant details and report sections, while hiding dashboard controls and validation panels.

Use `Publish Word` to download a Word-compatible `.doc` file generated from the same property report and publishing fields. The exported document embeds the logo as a data URI so the file can be opened in Word with the branding intact.

The generated report includes a raw query evidence table followed by production figure plates:

- a raw ERF query and Land Parcel cadastre extract showing submitted query, match method, match type, match basis, property number, SG26, ISIS/LIS key, legal status, address, extent, boundary length and WGS84 extent.
- Figure 1 locality map using Esri World Topographic tiles with selected parcel, nearby ERF markers, road/contour overlays where available, scale and north arrow.
- Figure 2 aerial photograph using Esri World Imagery with the selected ERF boundary when live cadastre is matched.
- a Surveyor-General / cadastral verification plate using City Land Parcels geometry, selected parcel, surrounding City erven, nearest surrounding ERF labels, road centreline context where available, parcel metadata, WGS84 extent and source notes. The official SG diagram and noting sheet must still be attached for submission.
- Figure 5 zoning map using City Split Zoning polygons. Because the live City QA Split Zoning FeatureServer can return ArcGIS query errors, the dashboard first tries the live endpoint and then falls back to the locally synced Split Zoning GeoJSON cache. If neither source is available, it can use the live Land Parcels `ZONING` attribute as a clearly labelled fallback.

The dashboard withholds schematic/fake geometry. Missing source evidence is shown as an evidence gate rather than an invented figure.

## ERF Query And Report Workflow

The primary workflow uses the search-confirm-retrieve pattern:

1. **Search**: Enter an ERF number (e.g. `187`), SG26 code or ISIS/LIS key in the main search bar and press Enter or click "Search City parcels".
2. **Confirm**: If multiple parcels match, the dashboard shows summary cards for each candidate (ERF number, suburb, ward, extent, zoning, address). Click the correct property to confirm.
3. **Retrieve**: Once confirmed, the dashboard automatically pulls all required report data from public City GIS sources — Land Parcel boundary, surrounding erven, roads/contours, Split Zoning polygons and City identify fields.
4. **Publish**: When required data is ready (cadastre + zoning figure source), use Publish PDF or Publish Word to produce the TBTP report.

If the search returns a single exact match, it is auto-confirmed and data retrieval begins immediately.

You can also click a City database ERF polygon in the map viewer. The selected parcel is converted into a City Land Administration record, confirmed automatically, and report data is retrieved.

A secondary "Direct lookup" input remains available for known SG26 codes or ISIS/LIS keys that should bypass the search-confirm step.

Use `Pull all report data` to re-fetch the selected ERF's required and supporting data at any time. Publishing unlocks when required data is available:

- Land Parcel cadastre: required.
- Figure 5 zoning source: required, using live Split Zoning, cached Split Zoning, or Land Parcels zoning attribute fallback.
- Surrounding erven, roads/contours and City identify fields: supporting evidence. These improve figure and report quality but do not permanently block publishing when required data is already present.

Typical wait times are shown in the dashboard readiness bar. City Land Administration lookup usually takes about 5-20 seconds; required figure data usually takes about 5-15 seconds after the parcel is matched; supporting evidence such as roads, contours and City identify fields can continue for about 10-30 seconds without blocking publishing once required data is ready.

## Local CSV Format

Required columns:

```csv
erfNumber,address,suburb,sizeSqm,zoningCode,zoningName
```

Optional columns:

```csv
sg26Code,parcelPropertyNumber,ward,scheme,overlay,permittedUses,consentUses,floorFactor,coveragePercent,heightStoreys,parkingNote,constraints,valueSignals,mapX,mapY
```

Use `sg26Code` where possible for the cleanest City Land Parcels match. If it is not available, `parcelPropertyNumber` can be supplied from the municipal parcel record; otherwise the dashboard falls back to erf number plus suburb, then address plus suburb.

Use semicolons inside list fields such as `permittedUses`, `consentUses`, `constraints` and `valueSignals`.

The repository includes `public/sample-local-properties.csv` for a quick import test from the dashboard.

## Public Data Research

The City of Cape Town Open Data Portal reported 244 public datasets and 134 spatial layers on 2026-07-09. Spatial layers are served live from municipal systems, so metadata dates do not necessarily equal source data refresh dates.

The dashboard currently audits 19 planning-relevant public layers before import:

- 1,156,897 records across the audited subset.
- Approximately 2,162.9 MB raw geometry-inclusive JSON, estimated from 25-record samples.
- Largest sampled layers: Ground Level Map 2m Contours at about 73,245 records and 1,155.4 MB, Land Parcels at about 843,207 records and 659.3 MB, and TCT Road Centerline at about 110,125 records and 170.9 MB.

Recommendation: do not bulk import every public metro layer into the browser. Start with phase 1 layers and sync them server-side into GeoPackage, PostGIS, SQLite/SpatiaLite or another indexed local store, then expose erf lookups to the dashboard.

For the report locality map and 3D explorer, the production data step is to clip TCT Road Centerline, Land Parcels, Ground Level Map 2m Contours and the GLM 5m DEM around the selected erf in the server-side sync process. The demo now visualises road and elevation context but does not claim surveyed elevation accuracy until those geometries are synced and validated.

## Layer Freshness Checks

Each `npm run build` runs `npm run check:data-updates` first. The checker reads each layer's ArcGIS item metadata and compares the live `created` and `modified` dates with the stored `lastPublishedAt` and `lastUpdatedAt` values in `src/data/publicDataInventory.ts`.

The checker writes `src/data/generatedLayerFreshness.ts` with one of three statuses:

- `current`: the stored baseline matches the latest public metadata date.
- `needs update`: the public layer metadata is newer than the stored baseline.
- `check failed`: the metadata endpoint could not be checked, so the layer should be reviewed manually.

This process intentionally does not import, refresh or overwrite public GIS datasets. It only marks whether a layer needs an update review.

## Local City Cache

Figure 5 requires Split Zoning polygons. The live City QA Split Zoning FeatureServer is public but can fail direct REST queries. To keep Figure 5 deterministic, sync the Open Data GeoJSON cache before production builds:

```bash
npm run sync:required-data
```

The cache is written to:

```text
public/city-cache/split-zoning.geojson
```

The sync also writes a manifest with source URL, feature count, byte size, sync date and spatial bounds:

```text
public/city-cache/manifest.json
```

Each `npm run build` now validates both public metadata freshness and required local cache availability:

```bash
npm run check:data-updates
npm run check:city-cache
```

If the Split Zoning cache or manifest is missing or invalid, the build fails with instructions to run `npm run sync:required-data`.

## Public Data Sources To Integrate

- City of Cape Town Open Data Portal: cadastral, zoning and planning overlay layers where published.
- City Map Viewer: municipal parcel and zoning desktop verification.
- TCT Road Centerline: municipal road-centreline geometry for access, hierarchy and frontage checks.
- Ground Level Map 2019: 2 m contour vectors and 5 m DEM derived from 2019B LiDAR for EGL, slope and height-context checks.
- Chief Surveyor-General: diagrams, cadastral history and servitude checks.
- Development Management Scheme: manual control and use-right verification before advice.

## Commands

From the workspace root, use the bash launcher:

```bash
./run-dashboard.sh
```

You can also choose a port:

```bash
PORT=5175 ./run-dashboard.sh
```

Or run the app directly from this folder:

```bash
npm install
npm run dev
npm run sync:required-data
npm run check:city-cache
npm run build
npm run lint
```

The bundled starter records and public data audit are for workflow testing and import planning. Live planning advice should confirm City of Cape Town zoning extracts, title deed restrictions, SG diagrams, overlays and current scheme controls.
